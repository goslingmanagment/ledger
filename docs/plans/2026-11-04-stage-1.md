# Этап 1: ядро ledger, план по PR

**Объём:** около 3,9 тыс. строк Go с тестами и деплоем, 8 PR.
**Спека:** `docs/specs/2026-11-04-ledger-design.md`.

## Порядок

```
PR1 каркас → PR2 проводки → PR3 импорт журнала → PR4 Bybit ─┐
                                    └→ PR6 SQL для агентов  ├→ PR5 бриф → PR7 проверки → PR8 переключение
```

- PR6 можно делать параллельно с PR4: он зависит только от PR2.
- До PR8 канон журнала остаётся в /OS `finance/ledger.md`, ночной разбор идёт по-старому, ledger работает в тени.
- `ledger-sync` после переключения ещё неделю остаётся запасным путём.

## Что нужно от владельца

1. **Ключ Bybit для сервера:** только чтение, с привязкой к IP `agency-de`. Положить в `~/.config/agency/secrets.env` как `LEDGER_BYBIT_API_KEY` и `LEDGER_BYBIT_API_SECRET`; на сервер его перенесёт агент. Нужен к PR4.
2. **DNS-запись `ledger.gosling-agency.ru`** на IP `agency-de` в reg.ru. Нужна к PR1.

Остальное агенты делают сами.

## PR1. Каркас и деплой (около 450 строк)

- `go.mod`, один бинарник `cmd/ledger` с подкомандами (`serve`, `sql`, `export`, …), настройки из env, `/health` с версией.
- Docker-образ без cgo, `compose.yml`:
  - контейнеры `ledger` и Litestream;
  - том `ledger_data`;
  - реплика `file:///data/replica/ledger`.
- `deploy/` по образцу TaskIndex:
  - `release.sh`, `deploy.sh`, откат;
  - `pull-backup.sh` и launchd на маке раз в 6 часов, копии в `~/Backups/ledger/`;
  - сайт nginx и сертификат.
- CI на GitHub Actions: `go build`, `go vet`, `go test`.
- **Готово, когда:**
  - `https://ledger.gosling-agency.ru/health` отвечает версией;
  - первая копия пришла на мак;
  - локальный прогон восстановления из копии прошёл.

## PR2. Схема и проводки (около 450 строк)

- Миграции SQL только вперёд, встроены в бинарник: `events`, `accounts`, `entries`, `lines`, `periods`, `proposals`, `disputes`, `rules`, `notes`, `observations`, `checks`, `keys`, `query_log`.
- План счетов из спеки заводится миграцией.
- Запись проводки одной транзакцией. Если сумма строк не ноль, запись отклоняется.
- События идемпотентны по `(source, source_id)`.
- Сторно: `reverse(entry, причина, спор)` пишет зеркальную проводку и не трогает исходную.
- Закрытие месяца пишет `locked_at`. Запросы «на закрытии» и «сейчас».
- **Тесты (это деньги):**
  - несходящаяся проводка не записывается;
  - повтор события не создаёт дубль;
  - сторно сохраняет исходник;
  - «на закрытии» не видит поздних исправлений.
- **Готово, когда:** тесты зелёные, `ledger post` из JSON работает локально.

## PR3. Импорт журнала и зеркало (около 650 строк)

- Разбор таблицы `ledger.md`: 11 колонок плюс текстовые блоки (шапка, паузы, срезы учёта).
- Разбор тегов с той же строгостью, что у `month.py`: неизвестный или битый тег останавливает импорт.
- Сопоставление «Тип/Категория/Метод/Модель» → счета. Неизвестные значения останавливают импорт со списком строк.
- Стартовые остатки задаются параметрами команды, в коде их нет:
  - выравнивание `bybit` на 2026-08-03;
  - выравнивание карт на 2026-08-01.
- `ledger export ledger-md` печатает журнал обратно в нынешнем формате.
- На проде: `ledger import ledger-md <файл>`. Файл копируется на сервер через scp и в репозиторий не попадает.
- **Тесты на синтетике:** туда и обратно без потерь; каждый тег; неизвестный метод.
- **Приёмка на реальных данных:**
  - `diff` между экспортом и текущим `ledger.md` пустой;
  - остаток `bybit` на 2026-08-31 и 2026-09-30 совпадает со сверками `closes.md` с учётом описанных там поправок.

## PR4. Сбор Bybit (около 800 строк)

- **Клиент Bybit v5** (подпись HMAC): депозиты, внутренние депозиты, выводы с повторной проверкой по id, P2P, журнал Funding. Баланс раз в час пишется в `observations`.
- **Планировщик:** каждые 15 минут, окно с нахлёстом 72 часа, дубли отсекает уникальность событий.
- **Правила:** точное совпадение uid, адреса или мерчанта с датами действия → проводка `auto`. Всё остальное становится предложением.
- **`ledger rules import`:** одноразовый перенос правил контрагентов, мерчантов и заметок атрибуции из локальных файлов `ledger-sync`. Запускается с мака в API прода, файлы в репозиторий не попадают.
- **`ledger import bybit-state <bybit.sqlite>`:** связывает историю Bybit с уже импортированными строками журнала по отметкам `mark` (`brief_items.ledger_rows`). Старые движения не всплывают в брифе заново.
- **Готово, когда:**
  - новое движение на проде появляется в `events` не позже чем через 15 минут;
  - движение известного контрагента проводится само;
  - у событий с 2026-08-01 нет несвязанных, кроме решённых как «личное».

## PR5. Бриф, decide и сборщик карт (около 650 строк)

- **Бриф** собирается из открытых предложений, нумерация замораживается. Блоки «записал сам», «похоже, проверь», «не разобрался», в хвосте висящие пункты. Команды `ledger brief --text` и `ledger brief-sent`.
- **`ledger decide --brief N --set 1=confirm --set 2=personal --set 3=custom:…`.** Решение привязано к версии предложения; проводка, решение и отметка пишутся одной транзакцией. Повторное решение по закрытому пункту отклоняется.
- **Сборщик карт на маке** (`ledger collect cards`):
  - читает бот через `tg history` и разбирает покупки, загрузки, депозиты и анкоры остатка (перенос `cards.py`);
  - шлёт события в API;
  - держит локальную очередь с повтором;
  - запускается launchd раз в 30 минут.
- **Цепочка остатков карты** сверяется с анкорами бота.
- **Готово, когда:** одна ночь на проде в тени, и бриф ledger совпадает по пунктам с брифом `ledger-sync`. Владельцу он пока не уходит.

## PR6. Запросы агентов (около 400 строк)

- **Ключи:**
  - хранятся хешем, права read, propose, decide;
  - выпуск на сервере: `ledger keys create <имя> --scope …`;
  - файлы `~/.config/ledger/credentials` (chmod 600) на маке, winpc и в OpenClaw.
- **`POST /v1/sql`:**
  - отдельное соединение только на чтение;
  - `ATTACH` запрещён;
  - таймаут 10 секунд, до 10 000 строк;
  - каждый запрос в `query_log`.
- **Команды** `ledger sql`, `ledger schema` (русские описания таблиц и колонок).
- **Представления** `v_balances`, `v_month`, `v_open`.
- **Тесты:** `INSERT`, `UPDATE`, `DELETE`, `ATTACH` и запись через `PRAGMA` отклоняются; таймаут срабатывает.
- **Готово, когда:**
  - каждый агент выполняет `ledger sql "select …"` и получает строки;
  - попытка записи возвращает 403;
  - запрос виден в журнале.

## PR7. Проверки (около 350 строк)

- **Каждый час:**
  - ноль в проводках;
  - `bybit` против баланса API ±$1;
  - карты против анкоров ±$1;
  - полнота событий с 2026-08-01 через 3 дня;
  - дрейф закрытых месяцев ≥ $100;
  - возраст реплики.
- **`ledger health`** печатает сбои. Утренний health в OpenClaw переходит с `fetch.py health` на него.
- Возраст копии на маке проверяет сам `pull-backup.sh`.
- **Готово, когда:** намеренно испорченная синтетика даёт сбой, а проверки на проде зелёные.

## PR8. Переключение (около 150 строк и документы)

- **Ночь переключения:**
  - ручная запись в `ledger.md` останавливается;
  - финальный импорт;
  - проверка, что экспорт совпадает с файлом.
- **Ночная рутина OpenClaw** переходит на `ledger brief` и `ledger decide`; ночной джоб `ledger-sync` выключается.
- **Launchd на маке** раз в час выполняет `ledger export ledger-md` в /OS `finance/ledger.md`.
- **В /OS:**
  - скилл `finance` (процедура «разбери байбит» через ledger);
  - строка канона в `AGENTS.md` (журнал живёт в базе ledger, `ledger.md` стал зеркалом);
  - строка рутины `bybit-nightly`.
- **Готово, когда** прошла первая боевая ночь:
  - бриф пришёл из ledger;
  - ответ владельца применён через `decide`;
  - зеркало закоммичено в /OS;
  - `month.py check` проходит.
