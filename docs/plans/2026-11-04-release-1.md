# Выпуск 1: живая картина денег, план по PR

**Объём:** около 7,6 тыс. строк Go с тестами и деплоем, 13 PR.
**Спека:** `docs/specs/2026-11-04-ledger-design.md`.

**Вехи:**
- Основа (PR1–PR2) готова в первые дни.
- Переключение (PR13) не позже 2026-12-01.
- Ноябрь закрывается в ledger (10–18 декабря).

## Порядок

```
Основа, по очереди:   PR1 каркас → PR2 проводки
Параллельно, каждый в своём worktree после PR2:
                      PR3 журнал   PR4 Bybit   PR5 хаб   PR6 люди   PR7 SQL
Дальше:               PR8 бриф и карты      (после PR4)
                      PR9 деньги в пути     (после PR3, PR5)
                      PR10 карточка месяца  (после PR6, PR9)
                      PR11 свободные деньги (после PR6, PR9)
                      PR12 проверки         (после PR8–PR11)
                      PR13 переключение     (последним)
```

- До PR13 канон журнала остаётся в /OS `finance/ledger.md`, ночной разбор идёт по-старому, ledger работает в тени.
- `ledger-sync` после переключения ещё неделю остаётся запасным путём.
- Каждый PR сразу готовый, со своей проверкой «готово, когда». Тесты пишутся там, где ошибка стоит денег: проводки, импорт, начисления, карточка месяца.

## Что нужно от владельца

1. **К PR1:** DNS-запись `ledger.gosling-agency.ru` на IP `agency-de` в reg.ru.
2. **К PR4:** ключ Bybit только на чтение, с привязкой к IP `agency-de`. Положить в `~/.config/agency/secrets.env` как `LEDGER_BYBIT_API_KEY` и `LEDGER_BYBIT_API_SECRET`, на сервер его перенесёт агент.
3. **К PR5:** агентский ключ хаба для ledger (консоль хаба → Settings → агентские ключи): права `read:money` и `read:datasets` на все страницы. Положить в тот же `secrets.env` как `LEDGER_HUB_AGENT_KEY`.

Остальное агенты делают сами.

## PR1. Каркас и деплой (около 450 строк)

- `go.mod`, один бинарник `cmd/ledger` с подкомандами, настройки из env, `/health` с версией.
- Docker-образ без cgo, `compose.yml`:
  - контейнеры `ledger` и Litestream;
  - том `ledger_data`;
  - реплика `file:///data/replica/ledger`.
- `deploy/` по образцу TaskIndex:
  - `release.sh`, `deploy.sh`, откат;
  - `pull-backup.sh` и launchd на маке раз в 6 часов, копии в `~/Backups/ledger/`;
  - сайт nginx и сертификат.
- CI на GitHub Actions: `go build`, `go vet`, `go test`.
- **Готово, когда:**
  - `https://ledger.gosling-agency.ru/health` отвечает версией;
  - первая копия пришла на мак;
  - восстановление из копии прошло локально.

## PR2. Схема, документы и проводки (около 500 строк)

- Миграции SQL только вперёд, встроены в бинарник. Все таблицы из спеки. План счетов заводится миграцией.
- Запись документа с проводками одной транзакцией. Если сумма строк не ноль, запись отклоняется.
- События идемпотентны по `(source, source_id)`.
- Сторно не трогает исходник.
- Закрытие месяца: `locked_at` и снимок. Запросы «на закрытии» и «сейчас».
- `ledger post` из JSON для ручной проверки.
- **Тесты:** несходящаяся проводка; повтор события; сторно; «на закрытии» не видит поздних исправлений.

## PR3. Импорт журнала и зеркало (около 650 строк)

- Разбор `ledger.md`: 11 колонок плюс текстовые блоки (шапка, паузы, срезы учёта).
- Разбор тегов с той же строгостью, что у `month.py`.
- Сопоставление «Тип/Категория/Метод/Модель» → счета. Неизвестные значения останавливают импорт со списком строк.
- Стартовые остатки задаются параметрами команды.
- Учётная модель: строки до 2026-09-01 кассовые; с 2026-09-01 доход платформ и зарплаты людей проводятся через счета страниц и долгов. Пока PR5 и PR6 не готовы, такие строки висят на временном счёте «ждёт начисления».
- `ledger export ledger-md` печатает журнал обратно.
- На проде файл копируется через scp и в репозиторий не попадает.
- **Готово, когда:**
  - `diff` экспорта с текущим `ledger.md` пустой;
  - остаток `bybit` на 2026-08-31 и 2026-09-30 совпадает со сверками `closes.md` с учётом описанных там поправок.

## PR4. Сбор Bybit (около 800 строк)

- **Клиент Bybit v5** (подпись HMAC): депозиты, внутренние депозиты, выводы с повторной проверкой по id, P2P, журнал Funding. Баланс раз в час.
- **Планировщик:** каждые 15 минут, окно с нахлёстом 72 часа.
- **Правила:** точное совпадение → проводка `auto`, иначе предложение.
- **`ledger rules import`:** одноразовый перенос правил и заметок из локальных файлов `ledger-sync`.
- **`ledger import bybit-state <bybit.sqlite>`:** связывает историю Bybit с импортированными документами по отметкам `mark`, чтобы старые движения не всплыли в брифе заново.
- **Готово, когда:**
  - новое движение на проде появляется не позже чем через 15 минут;
  - известный контрагент проводится сам;
  - у событий с 2026-08-01 нет несвязанных, кроме решённых как «личное».

## PR5. Импорт хаба (около 700 строк)

- **Сервисный ключ хаба.** Выгрузка через Agent Read Plane:
  - `transactions`, `payouts`, `ofapi_payout_requests`;
  - балансы страниц (`page_profile_daily`, `pending_balance`).
- **Для каждой строки хранятся:** исходный id, время получения, пол захвата, блокеры. Чтение по правилам честности хаба: пустой ответ без покрытия получает статус «неизвестно».
- **`routes` и `hub_exceptions`** переносятся одноразовой командой из /OS (`finance/rules.md` § Маршруты, `finance/hub-exceptions.md`).
- **Платёж фана** даёт начисление на `page:<label>:hold`; конец холда по типам; заявка на вывод.
- **Готово, когда:** net по каждой странице за сентябрь и октябрь совпадает с колонкой «Оборот» `month.py show` на тот же срез.

## PR6. Долги людям (около 650 строк)

- **`ledger collect sheets`** на маке: читает таблицы выплат через `gog` с проверками формата `payroll.py` и шлёт ячейки дней событиями.
- **Начисление по дням** на `payable:<slug>` по ставке из ячейки «З/П». Выплаты из журнала гасят самые старые дни, `{сверх таблицы}` идёт в расход напрямую.
- **Сверка с хабом по окнам смен** (правила audit-payroll): дни «не занесено» показываются отдельно.
- **Готово, когда:**
  - `v_payables` по каждому человеку совпадает с «К выплате» его вкладки;
  - при ручной проверке одного человека за две недели все дни и суммы совпадают с вкладкой и хабом.

## PR7. Запросы агентов (около 400 строк)

- **Ключи:**
  - хранятся хешем, права read, propose, decide;
  - выпуск на сервере: `ledger keys create <имя> --scope …`;
  - файлы `~/.config/ledger/credentials` (chmod 600) на маке, winpc и в OpenClaw.
- **`POST /v1/sql`:**
  - соединение только на чтение;
  - `ATTACH` запрещён;
  - таймаут 10 секунд, до 10 000 строк;
  - каждый запрос в `query_log`.
- **Команды** `ledger sql`, `ledger schema` (русские описания), представление `v_balances`.
- **Тесты:** `INSERT`, `UPDATE`, `DELETE`, `ATTACH` и запись через `PRAGMA` отклоняются; таймаут срабатывает.
- **Готово, когда:** каждый агент получает строки через `ledger sql`, а запись получает 403.

## PR8. Бриф, decide и сборщик карт (около 650 строк)

- **Бриф** из открытых предложений с замороженной нумерацией. Блоки «записал сам», «похоже, проверь», «не разобрался», в хвосте висящие пункты. Команды `ledger brief --text` и `ledger brief-sent`.
- **`ledger decide --brief N --set 1=confirm --set 2=personal --set 3=custom:…`.** Решение привязано к версии предложения, всё пишется одной транзакцией. Повторное решение по закрытому пункту отклоняется.
- **`ledger collect cards`** на маке: бот через `tg history`, покупки, загрузки, депозиты и анкоры (перенос `cards.py`); очередь с повтором; launchd раз в 30 минут.
- **Готово, когда:** одна ночь в тени, и бриф ledger совпадает по пунктам с брифом `ledger-sync`.

## PR9. Деньги в пути и переводы моделей (около 700 строк)

- **Покрытие перевода по срезу**, как в `month.py`: последняя заявка любой платформы, FIFO заявок.
- **Счета `model:<slug>:due`.** Поправка k идёт проводкой через `income:true_up:<модель>`.
- **Пометка `{перевод}`** сверяется арифметически: депозиты × доля = зачислено + удержано.
- **Представление `v_in_transit`:** холд, доступно, заявлено, у модели, застряло (ниже минимума маршрута).
- **Готово, когда:** k всех переводов с сентября совпадает с таблицей «Переводы» `month.py show` до четвёртого знака.

## PR10. Карточка месяца (около 900 строк)

- **`v_month` и `ledger month show|close`:** оборот, заработано, пришло, в пути, застряло, расходы, цифра решения, вердикт предохранителя зарплаты владельца.
- **Блокеры закрытия** как в правилах учёта: в пути больше $100, нерешённые пункты брифа, k вне нормы, ошибки таблиц.
- **Снимок закрытия** неизменяемый; «сейчас» против «на закрытии».
- **Готово, когда:**
  - сентябрь воспроизводит `finance/months/2026-09.json` до цента;
  - октябрь совпадает с `month.py show 2026-10` на тот же срез.

## PR11. Свободные деньги (около 350 строк)

- **Таблица `commitments`** и одноразовый перенос реестра обязательств из правил учёта, зарплаты владельца и открытых статей реинвеста из `closes.md`.
- **`ledger free`:** свободно сейчас и после ближайших переводов, с разбивкой и временем последнего события по каждому источнику. Подушку задаёт владелец, по умолчанию она считается по формуле из спеки.
- **Готово, когда:** на одну дату ответ `ledger free` совпадает с ручным расчётом по тем же входам. Ручной расчёт делается по первичке: таблицы, хаб, журнал.

## PR12. Проверки (около 500 строк)

- **Все проверки из спеки** каждый час, `ledger health`.
- **Путь каждого доллара:** по каждому переводу модели видна цепочка «платежи фанов → заявки → депозиты из пометки перевода → зачисление». Обрыв звена даёт сигнал: заявка без перевода дольше 11 дней, депозиты не сходятся с заявками с учётом маршрута, k вне нормы.
- **Утренний health** в OpenClaw переходит с `fetch.py health` на `ledger health`. Срочные сбои (касса не сходится, перевод модели просрочен) приходят сразу.
- **Готово, когда:** испорченная синтетика даёт сбой по каждой проверке, а на проде всё зелёное.

## PR13. Переключение (около 250 строк и документы)

- **Ночь переключения:** ручная запись в `ledger.md` останавливается, финальный импорт, экспорт совпадает с файлом.
- **Ночная рутина OpenClaw** переходит на `ledger brief` и `ledger decide`; ночной джоб `ledger-sync` выключается.
- **Launchd на маке:** зеркало `ledger.md` раз в час.
- **В /OS:**
  - скилл `finance`;
  - строка канона журнала в `AGENTS.md`;
  - рутины `bybit-nightly`, `month-weekly` и `month-close` теперь вызывают `ledger`.
- **Готово, когда:** первая боевая ночь прошла (бриф из ledger, ответ применён, зеркало закоммичено), и `ledger month show` совпадает с `month.py` на тот же срез.
